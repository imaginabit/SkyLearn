{% load i18n %}{% comment %} Borrar por POST. Antes era un y Django no exige POST para destruir: un enlace de correo o de una imagen ajena bastaba para borrar. Quien lo llama resuelve la URL con {% url ... as borrar_url %} porque cada sitio pasa sus argumentos, y pasa la clase para que el boton siga teniendo el aspecto que tenía el enlace. El onsubmit pregunta antes de borrar: son cosas que no tienen vuelta atras (un curso, una cuenta, un fichero). Quien lo llama puede pasar `confirmar` con un texto mejor; el texto por defecto no lleva apostrofes porque va dentro de comillas simples en el javascript del onsubmit. {% endcomment %}
